实机旧结果仅有 `FAILED / TimeoutError`，业务处理计数0、日志为空。不能据此确认超时发生在PubSub读取、队列LPOP或其他阶段，也不能用计数0排除未取得应答的LPOP已移除请求。

接收顺序改为：非阻塞PubSub检查；若没有取得业务消息，对固定账户队列做只读LLEN；长度为0直接返回空闲；长度为正才执行一次LPOP。正常非空队列及PubSub请求仍沿原协议转发，不改变请求顺序、原生方法或回复形状。

只有本次poll尚未取得PubSub业务、且没有发出LPOP时，LLEN的明确Redis超时允许下轮重新检查。连续第三次LLEN超时封闭代理；成功检查重置连续计数。该重检不消费业务、不执行原生调用、不触碰写账本、不重复响应发布。Redis库级重试仍为0，连接读写超时仍有限；Redis客户端增加15秒原生连接健康检查，用于保持闲置订阅，未增加服务或后台线程。

PubSub读取或订阅失败、LPOP失败、SHM调用或响应验证失败、写账本失败以及回复发布失败，均保留原封闭行为。LPOP及PubSub超时可能已经消费业务；写调用及部分发布可能已经生效，均不自动重发、重新订阅或解除UNKNOWN。持久写记录不删除、不回收。
